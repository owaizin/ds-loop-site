The problem

Every new screen adds another set of decisions.

Your app has a shared input, but the billing form builds its own. The settings screen hardcodes a color that already has a token. As people and agents ship changes, the code drifts from the system you agreed on.

An agent can repeat the same mistake when it cannot find your library. DS Loop helps it find the right component, use a checked example, and save the decision for the next change.

Connect DS Loop to your coding agent

Install and connect See an example report

Open source · Checks run locally
Node 22.6 or later · Alpha · review changes before shipping

  1. Install

    Run npm install -D ds-loop@latest in your project to add the package and bundled skill.

  2. Connect your agent

    Choose your host: claude, codex, or cursor. For Codex, run npx ds-loop install --agent codex. Replace codex with your host’s name. Agent setup instructions.

  3. Start

    Ask your coding agent to read node_modules/ds-loop/skill/SKILL.md and investigate your project. Review the proposed plan and approve the work before it makes changes.

Before you install

What makes the design system LLM-ready?

Can a fresh agent find the right component, use its actual API, and check the result without you supplying every detail? DS Loop helps you connect the components, examples, and project decisions it needs, then try a representative task. That task shows what works and what still needs attention.

Why use it if my agent already has DESIGN.md?

Keep your DESIGN.md. DS Loop helps your agent turn that guidance into shared components, checked changes, and updated documentation.

Do we need a design system already?

No. Your agent can help you start one. If you already use a component library, it should look at what you have before suggesting a replacement.

What does it check, and what doesn’t it?

The engine reads CSS custom properties and selected rule properties, Tailwind values in JavaScript and TypeScript strings, DTCG and Style Dictionary token JSON, and SCSS/Sass. Rendered layouts, interactions, accessibility, and design quality need separate review. Read the exact coverage.

Does it run in the background?

The optional Claude Code hook reports findings after edits; it does not block them. You can also configure CI to fail on selected findings or coverage gaps. Installing the package does not schedule checks or start ongoing maintenance.

Does it replace shadcn/ui or require Storybook?

You can keep shadcn/ui or another suitable library. Storybook is optional; component examples and a usage guide may be enough to start.

What does it cost, and where does our code go?

The package and skill are open source under MIT. The engine runs locally without model calls, API keys, or network access. Your coding agent’s costs and data handling depend on its provider and your settings.
