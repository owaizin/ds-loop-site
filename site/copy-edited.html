Give your agent a place to start.

Pick a screen or component you want to improve. Tell your agent what bothers you and what needs to stay the same.

  1. Point to the problem

    “Our billing form uses its own inputs. Help us use the shared ones without changing how the form works.”

  2. Set the boundaries

    Name the screens to change, the existing components to keep, and any differences the product needs.

  3. Review the result

    Try the changed screen. Read the code changes, test results, and usage notes. Ask what still needs checking before you ship.

Before you install

What should a setup deliver?

Tokens and components used in the screens you agreed to change, plus examples and instructions for your team. Follow the setup steps.

Do we need a design system already?

No. Your agent can help you start one. If you already use a component library, it should look at what you have before suggesting a replacement.

What do the skill, engine, and team each do?

The skill gives your agent instructions for the work. The engine runs local token and styling checks. Your team chooses priorities, reviews design decisions, and decides when to ship. Connect the skill to your agent after installing the package.

Does it replace shadcn/ui or require Storybook?

You can keep shadcn/ui or another suitable library. Storybook is optional; component examples and a usage guide may be enough to start.

When is the work finished?

The screens you chose use the shared components, the relevant checks have run, and your team has instructions for using and changing them. The notes should also say what hasn’t been tested.

What does it check automatically?

The engine reads CSS custom properties and selected rule properties, Tailwind values in JavaScript and TypeScript strings, DTCG and Style Dictionary token JSON, and SCSS/Sass. It does not review layouts, interactions, accessibility, or design quality. Read the exact coverage.

Does it work in the background?

No. You or your agent start the work. An optional Claude Code hook reports findings after supported edits; it doesn’t block or fix them. You can set up CI checks separately. DS Loop is in alpha, so review changes before shipping.

What does it cost, and where does our code go?

The package and skill are open source under MIT. The engine runs locally without model calls, API keys, or runtime network access. Your coding agent’s costs and data handling depend on its provider and your settings.
