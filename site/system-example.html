What we changed

Each before-and-after pair keeps the same product task. Shared foundations improve layout, controls, and labels while leaving room for differences between screens.

AreaIndependent implementationsShared foundation
Page structureCompeting page spacing, headings, and control density.Shared spacing and type scales, with a composition suited to each task.
ControlsFeature-specific colors, button shapes, search, and filter treatments.A common action style and matching control conventions.
Repeated dataDense chart labels, form fields, planning cards, and review notes.Clear data hierarchy, field grouping, card structure, and discussion rhythm.
Status languageStatus treatments compete with content and vary between product areas.Shared labels and appearances for equivalent states.
Product differencesAnalytics needs a chart; project creation needs a form; planning needs a board; review needs a canvas.Each screen keeps its purpose and composition while sharing the underlying conventions.

Using Design System Loop for this work

DS Loop helps your coding agent investigate the existing screens, propose shared patterns, and carry out the work your team approves. Local checks provide code evidence; your team and agent decide what to change and what to keep.

Your team and agent need to inspect the layout, content hierarchy, and status terminology. These require design judgment beyond the engine’s code checks.
