Read findings and saved reports

Find the source of a finding before changing your code:

npx ds-loop audit .

These excerpts are checked against the engine by test/readme.test.ts. Line wrapping and marked truncation are permitted. Summaries use clear words; --all and JSON preserve the engine vocabulary.

The │ gutter groups the lines of one finding and is always emitted. In a terminal, long where:, risk: and fix: lines wrap to the window width and continue under their label; piped or redirected output keeps each on one line, so a captured log and these excerpts stay comparable. Colour follows the same rule — severity tags are coloured only on a terminal, and NO_COLOR turns that off.

Use these examples to read CSS inventory, token suggestions, coverage gaps, unsupported sources, and changes over time. All marked output is checked against a real command run.

Ordinary CSS inventory

From the repository root, run:

npm run ds-loop -- audit fixtures/css-audit-example

This independently written Example DS fixture contains a colour literal, a spacing literal and two references. The inventory precedes severity and exception filters; its ratio does not prove the references resolve.

A token suggestion

The same run finds an exact colour candidate through a project alias. This is a review candidate, not permission to replace the value. JSON retains the primitive candidate too, plus alias provenance and resolution limits.

  │ suggest:#333: ambiguous — --ds-color-text, --ds-palette-gray-700. Value candidates only; cascade, mode, semantic role and replacement safety are not established. No automatic replacement. Full candidates, alias provenance and resolution limits in --json.

Consulting report generation

From the source checkout, run:

npm run ds-loop -- report fixtures/css-audit-example --out scratch/phase-1/css-report.html


  ds-loop report — ds-loop
  wrote scratch/phase-1/css-report.html

Open the written HTML for findings, architecture and coverage. Without --consult consult.json, the assessment and plan are labelled as not written yet. The banner uses the source label; this fixture resolves to ds-loop.

Dashboard generation

npm run ds-loop -- dashboard fixtures/css-audit-example --out scratch/phase-2/dashboard-empty.html

The following is captured command output; dates and ratios are in the generated HTML. With no saved history, the dashboard shows today's measured state and the baseline command.

  ds-loop dashboard — ds-loop
  wrote scratch/phase-2/dashboard-empty.html

Limits

report and dashboard write artifacts; successful generation isn't a clean audit or a CI pass. Run audit --require-coverage for that policy. Dashboard samples above were captured in an empty temporary working directory with the fixture passed by absolute path, so no saved history affected the result. The report sample used the same setup. Dates and ratios belong to the generated HTML.
